# GitHub Pages Deployment

## Setup Instructions

To enable GitHub Pages deployment for the spellbook:

1. **Enable GitHub Pages in Repository Settings**
   - Go to your repository settings
   - Navigate to "Pages" section
   - Under "Build and deployment", set:
     - Source: **GitHub Actions**
   
2. **Configure Base Path** (if needed)
   
   The workflow is configured to deploy to `/dnd354ever/` by default. If your GitHub Pages site structure is different, you can:
   
   - Edit `.github/workflows/deploy-spellbook.yml`
   - Change the `BASE_URL` environment variable in the build step
   
   Common configurations:
   - Root of Pages site: `BASE_URL: /`
   - Subdirectory: `BASE_URL: /spellbook/`
   - Custom domain: `BASE_URL: /`

3. **Trigger Deployment**
   
   The workflow will automatically run when:
   - You push changes to the `main` branch that affect the `spellbook/` directory
   - You manually trigger it from the Actions tab
   
4. **Access Your Site**
   
   After deployment, your site will be available at:
   - `https://<username>.github.io/<repo>/` (with default config)
   - Or wherever you configured it to deploy

## Workflow Details

The GitHub Actions workflow performs these steps:

1. **Test**: Runs all unit tests and linter
2. **Build**: Compiles the React app for production
3. **Deploy**: Deploys the built files to GitHub Pages

## Local Testing

To test the production build locally:

```bash
cd spellbook
npm run build
npm run preview
```

This serves the production build locally so you can verify everything works before deploying.

## Troubleshooting

### Assets not loading
If CSS/JS files are not loading after deployment, verify the `base` path in `vite.config.ts` matches your GitHub Pages URL structure.

### 404 on page refresh
GitHub Pages with client-side routing requires special handling. The current setup should work, but if you experience issues, you may need to add a 404.html redirect.

### Build fails
Check the Actions tab for detailed logs. Common issues:
- Tests failing (fix the tests)
- Linting errors (run `npm run lint` locally)
- TypeScript errors (run `npm run build` locally)
